# 本机 AI 查询代理

## 实施前失败场景

- Agent 宿主没有磁盘权限时仍直接读库，或代理失败后悄悄回退直读。
- 代理复用原生子进程的本人浏览豁免，导致黑名单失效。
- 客户端传入路径、profile、凭据、任意子命令，替换应用已连接来源。
- 黑名单更新、损坏、权限异常后长驻服务继续返回旧授权数据。
- 切换来源、断开或退出后旧服务仍持有凭据并接收请求。
- 假冒 socket、符号链接、跨用户连接、超长请求、半开连接或超长响应。
- 查询/搜索/分页/附件格式发生变化，或查询词、正文、凭据进入诊断日志。
- 更新签名身份或工具摘要后自动连接丢失；安装验收未执行便声称完成。

## 约定

日常 `source status`、`chats`、`conversations`、`contacts`、`messages`、
`message`、`attachment` 查询使用应用管理的私有 Unix socket。应用连接成功后
启动服务，断开/切换/退出时关闭。凭据仅通过匿名管道进入服务及其查询子进程，
不写文件、参数或环境变量。每次查询在独立工具子进程中执行原有查询与黑名单
逻辑；其父进程为代理工具而非原生应用，因此没有本人浏览豁免。

服务只接受固定查询命令与参数，来源和访问方式由应用注入；不接受客户端
profile、来源路径、访问方式或凭据。默认客户端不读来源配置或数据库，代理
不可用时先静默后台启动并等待已有连接恢复；仍不可用则报错，不打开 UI，也不要求给 Agent 授予磁盘权限。
显式指定来源的旧管理/离线命令保留，日常 Agent skill 不使用这些入口。

## 验收

使用独立账户合成进程 E2E 验证列表、分页、搜索、精确消息、动态黑名单、
非法参数和服务消失，保存脱敏 JSON。随后完成完整 local-ci、同身份安装、
原生冷启动自动重连、实际受限查询和再次重启验收。真实数据只记录布尔结果，
不发布原生聊天截图。

## 生命周期与限制

socket 位于系统账户 home 的 `Library/Application Support/GreenBubbles/query.sock`，
目录 0700、socket 0600，并检查同用户 peer。请求上限 64 KiB，响应上限
16 MiB，连接读写和查询子进程均有截止时间。应用退出时终止服务；应用异常
退出由服务监测直接父进程并退出。残留 socket 仅在验证所有权、类型、权限且
不能连接后清理。不监听 TCP，不接受任意 shell 命令，不自动下载附件。

日常查询不枚举钥匙串，不读取旧 CLI 凭据文件。应用只在连接验证成功后启动
代理，复用已有凭据；切换来源先停止旧代理，游标继续绑定原来源。显式离线
管理入口仍属于同用户本机工具，不能视为操作系统级隔离；本次不撤销既有
App 的系统权限，也不声称可以控制任意程序自行读取文件。

最终安装 build 79：原生冷启动自动恢复、客户端沙盒禁读后查询通过、空请求拒绝且服务保持可用。代理专项含动态黑名单正反例；真实策略文件逐字节保持不变。

## 静默启动：实施前失败场景（2026-11-19）

- CLI 为查询调用普通 `open`，或应用启动/状态栏初始化/窗口 onAppear 任一处抢前台。
- 不显示窗口后，连接恢复仍依赖 view.task，导致后台永远没有代理。
- 应用已运行但窗口关闭、隐藏或最小化时，重复查询触发 reopen/激活。
- 并发冷启动重复打开应用；代理启动超时无限等待或回退直接读库。
- 已发送的请求被重试，导致附件保存重复执行。
- 后台启动污染用户 Dock 偏好，或用户主动打开时无法恢复唯一窗口。
- 无已记住连接、权限失效时自动展示设置页、索取密钥或要求 AI 宿主磁盘权限。
- 自动恢复过程改写黑名单、钥匙串连接或签名身份。

静默入口为应用参数 `--background-query`，仅恢复已有连接。普通 CLI 查询先连接
socket，仅连接失败才在 macOS 通过 LaunchServices 后台且隐藏启动已安装应用；
已运行应用不发送 reopen。启动和 socket 等待有界；已发出的请求不自动重放。
用户主动从 Dock/Finder/菜单打开时恢复普通窗口行为。首次缺少连接时返回错误，
由用户决定何时进入设置，不因查询自动打开聊天或连接窗口。

静默启动使用同目录 0600 的短时启动标记补足 LaunchServices 立即重启时可能丢失 argv 的情况；标记仅包含时间戳、30 秒有效，应用读取后或 CLI 启动等待结束即删除，不保存用户偏好或任何凭据。并发启动由私有 flock 合并。
