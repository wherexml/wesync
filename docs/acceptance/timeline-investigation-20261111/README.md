# 会话切换、滚动与陈旧缓存验收

2026-11-11，安装版 **we-sync 0.10.0（72）**。修复了可重复的陈旧缓存路径，并将加密缓存读取、解密、解码和头像恢复移到后台。两次原生退出重开均自动连接，无凭据输入；设置、关于、刷新和消息滚动通过。候选与安装主程序在两次启动后摘要一致，原 helper 字节及签名身份保留。详情见 [summary.json](summary.json)。

## 安装版耗时

相同大/小会话交替六次，加载量为 265 / 7 条。初次 AppKit 探针布局不等于屏幕呈现；滚轮投递不等于帧率。

| 观测项 | 结果 |
| --- | --- |
| 修复前切换首次布局中位数 | 79.4 ms |
| 最终版切换首次布局中位数 / 范围 | 66.6 ms / 49.8–140.8 ms |
| 六次滚轮事件投递范围 | 0.24–6.11 ms |
| 连续滚动窗口最大主线程定时器间隔 | 93.0 ms |
| 切换/滚动观测全过程最大间隔 | 223.2 ms |
| 加入设置/菜单和一次 AX 越界错误后的最大间隔 | 3646.9 ms |
| 合成大缓存恢复最大心跳间隔，修复前 → 后 | 1517.3 → 302.3 ms |

仍有主线程调度停顿，不能声称卡顿消除，也不能仅凭这些间隔断言某个函数连续阻塞同样时长。3.65 秒发生在菜单/辅助功能异常过程，取消菜单并重新提升窗口后完成退出；不归作聊天布局耗时。六次样本不能证明显著加速。异步正文查询约 2.5–2.6 秒，单列于 [performance.json](performance.json)，不作为缓存点击延迟。[采样符号计数](sample-symbols.json) 是修改前两段 30/25 秒采样中的包含计数，不能相加成时间占比；原始采样留在本机。

诊断默认关闭，仅记录固定类型、耗时、数量和布尔值。测量后恢复原偏好并冷启动，确认诊断文件无新增写入。未操作微信、修改源聊天、枚举钥匙串或重置权限。

## 缓存缺陷与现场边界

合成来源读取 80 条后删除第 61 条，保持摘要与最近日期不变。旧实现只核对最近 40 条并拼回旧尾部，导致删除的记录继续显示。[修改前失败](reconciliation-before.json) 已保留。现在可靠读取核对已加载窗口，最多 400 条；文件变化即使摘要不变也触发核验，来源穷尽时不拼回旧尾部。失败/部分覆盖保持可读内容，目录任一页覆盖不完整时不移除旧会话。

用户反馈是“we-sync 有，同一台 Mac 微信没有”。尚无具体会话、消息时间可核对，**没有证明现场问题与此同因**；不根据猜测的状态字段过滤源记录。

| 原生合成 E2E | 结果 |
| --- | --- |
| [删除、撤回、自动变化、重启、失败、部分目录等](reconciliation.json) | 17/17 |
| [150 会话预热与加密恢复](preload.json) | 316/316，原有 500 ms 心跳门槛通过 |
| [连续分页、取消与磁盘缓存](message-cache.json) | 17/17 |
| [后台正文更新与历史锚点](body-refresh.json) | 11/11 |
| [完整本机 CI](local-ci.json) | 23/23 |

合计 361 项合成断言。核验 E2E 已包含最终目录保护；预热和磁盘缓存在异步恢复修改后、目录保护前通过；正文回归在恢复和目录跟进前通过，该场景关闭持久化。版本边界逐项记录于 summary.json，未将旧产物伪装成重跑结果。

曾有一次本机 CI 的隔离 Rust E2E 在 SQLCipher 初始化失败，Rust 源码未变、原因未确认；同源码完整重跑通过，最后目录保护修改后又完整通过 23 项，没有豁免或跳过检查。GitHub Actions 保持关闭；没有发布 DMG 或部署首页。
