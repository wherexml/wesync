# 会话列表持续刷新

## 修改前失效场景与 E2E 计划

- 长时间保持连接：源会话时间、摘要和排序更新，左侧仍停留在启动时的一轮读取。
- 点击聊天刷新：只更新正文，没有重新读取会话列表。
- 自动刷新与首次目录分页重叠：旧游标可能覆盖新目录，或丢失尚未补齐的会话。
- 更新首页：须按来源时间重新排序，保留未在首页出现的旧会话、当前选择、筛选和历史阅读位置。
- 刷新失败：保留旧列表，显示可重试错误；禁止无休止自动重试。
- 断开或更换来源时正在刷新：旧结果不能覆盖新来源。
- 新增及删除会话：自动刷新发现最新首页，主动完整刷新最终按来源全目录移除删除项。
- 同证书安装、原生退出重开：无需输入密钥恢复连接，左侧时间与只读来源一致；正文历史分页仍可读。
- 没有源变更时保持静默，不定时启动查询；突发 WAL 写入合并，相邻自动读取至少间隔 60 秒。
- 数据库/WAL 轮换后重新绑定监听；后台仅标记待更新，回到前台处理，失败暂停自动重试。
- 同一会话行的摘要与日期同时更新；时间控件不能复用旧日期闭包，禁止通过切换分类掩盖标签未刷新。
- 合成原生 E2E 在保持同一会话行可见时，将其消息日期推进一分钟，保存真实窗口的前后截图与预期时间；人工核对合成行标签直接变化，不保存真实聊天截图。

采用独立合成原生应用与真实子进程 transport 验证上述失效场景，输出脱敏 JSON；再完成安装版重启验收。禁止使用真实聊天正文、联系人标识或未审查截图作为仓库证据。

## 当前规则

- 本机只读来源和已解密来源监听会话数据库与 WAL 的文件变化，只查看元数据、不打开数据库正文。源变更才标记待刷新；没有变化不启动查询。加密备份不启用自动监听。
- 文件事件先合并等待至少 2 秒，自动读取与上次读取至少间隔 60 秒。连续消息保持最多每分钟一轮，安静后没有周期性查询。后台保留待更新标记，回到前台按相同限频规则处理。
- 监听包含来源目录、session 目录、`session.db` 和可选 WAL，共最多四个文件描述符；忽略 SHM 与无关目录变化。数据库/WAL 轮换后重新绑定。原有每分钟日期任务只检查元数据作为漏通知兜底，仍不在无变化时读库。
- 自动刷新合并最新首页，按归一化消息时间降序、会话标识升序重新排序，同时保留目录尾部。时间、摘要、头像与排序使用新来源记录；分类、筛选、选择和已读消息页不重置。
- 首次全目录分页或主动全目录刷新尚未完成时，跳过自动刷新，避免两条分页链争用。刷新查询只能同时存在一个；自动查询期间的主动刷新会合并为随后的一轮完整刷新，不丢失用户请求。
- 右上角“刷新”同时重新读取目录首页、后台补齐全目录，以及读取当前聊天最新消息。成功补齐全目录后移除来源中已删除的会话。
- 自动刷新只覆盖最新 100 项，不宣称每轮全目录同步；大量会话同时变化或删除旧会话时，主动刷新完成全量核对。
- 刷新失败保留原列表并显示“重试”；暂停自动读取，用户重试或主动刷新成功后恢复。目录分页失败继续使用原来的分页重试。文件监听无法建立时提示使用刷新按钮，不降级为高频查询。
- 断开或更换来源取消刷新、轮换请求标识，检查来源和请求后才接收结果。凭据仍由现有连接在内存中供给、用后清零；不重新授权或替换工具。
- 查询成功后只在目录内容变化时保存加密缓存；来源变化但消息时间、摘要等内容未改变时不重复写缓存。每分钟的日期标签和时间范围判断继续独立更新。本文不改变正文的 15 分钟分隔阈值。

## 重复 E2E

1. 执行 `python3 scripts/package-presentation-preview.py --polish`，仅构建独立合成应用。
2. 在 `.local-install/GreenBubbles Polish Preview.app/Contents/Resources/offline-fixture/` 创建空文件 `conversation-refresh-acceptance`；删除同目录上次的 `conversation-refresh-fail`、`conversation-refresh-slow`、`conversation-refresh-stage` 与 `conversation-refresh-acceptance.json`。
3. 原生退出旧预览并重新打开，让窗口保持前台至少 90 秒。生产文件监听必须发现合成 WAL 的真实写入与替换；生产调度使用单调时钟，合成 transport 用跨进程共享的 Unix 时间记录实际读取间隔。验收不通过直接调用替代事件触发。
4. 查看同目录 `conversation-refresh-acceptance.json`，检查所有断言为 true。覆盖静默 20 秒不查询、SHM 噪声不查询、后台延迟、60 秒限频、突发事件合并及 WAL 替换，同时保留 230 会话分页、新会话与排序、目录尾部、选择/筛选/80 条已读历史、失败暂停、完整主动刷新删除项、并发主动刷新与断开隔离。按 `conversation-timestamp-evidence.json` 核对真实合成窗口的 `conversation-timestamp-before.png` 与 `conversation-timestamp-after.png`，同一已选会话时间应推进一分钟，分类和筛选不变。
5. 使用同一稳定签名安装主应用，原生退出重开；不输入密钥自动连接，比较左侧时间与 bundled CLI 的有限只读查询结果，点击刷新并检查会话选择保持。只保存脱敏结论。
