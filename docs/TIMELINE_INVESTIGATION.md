# 会话切换、滚动与陈旧消息

## 反馈范围

2026-11-11 用户澄清：we-sync 中有消息，但同一台 Mac 上的微信中看不到。不能据此推断微信删除了数据；需要区分来源仍有记录、缓存陈旧、撤回内容更新与读取不完整。禁止直接操作微信，不根据未证实的 status 值过滤来源。

## 实施前失败场景

- 将辅助功能查询/自动化传输时间当成应用点击响应时间；采样只能解释命中的栈，不能证明没有短时阻塞。
- 诊断输出包含联系人、消息、ID、来源路径或凭据；诊断默认开启、无限增长、同步写主线程或不恢复开关。
- 启动在主线程解密/解码大缓存；移到后台后旧来源恢复晚到覆盖新连接、损坏缓存阻止新读取、缓存恢复与实时读取顺序颠倒，或改变磁盘格式及凭据作用域。
- 缓存命中后界面仍重建大量布局；滚动通知反复触发全量视图更新、头像解码/哈希和日期格式器创建。
- 源中删除较早消息或更新撤回正文，但最近摘要/日期不变，缓存刷新未被触发。
- 只核对最新 40 条，把旧缓存直接拼回；已删除旧记录在切换、重启后仍出现。
- 完整目录移除会话后，已选时间线仍留旧内容；未完成目录分页时错误移除有效会话。
- 目录前页覆盖不完整、末页正常时，错误把末页状态当成全目录可靠，移除仍有效的缓存与选择。
- 查询失败、覆盖不完整、翻页无进展、来源变化、较新请求覆盖旧请求时错误清空或复活旧消息。
- 刷新扩大读取后破坏历史锚点、连续游标、缓存容量或取消语义；不能把未知的未覆盖范围推断为已删除。

## 测量契约

先对安装版进行原生切换和滚动并采样；自动化耗时单独标注。增加默认关闭的本机内容无关诊断：事件投递延迟、切换处理到 AppKit 布局、查询耗时、主线程定时器间隔。记录仅含耗时、数量和布尔状态，固定私有路径、固定上限，后台写入；测量后恢复开关。布局完成不是屏幕物理呈现时间。

合成 CLI/native E2E 先复现删除旧消息而摘要不变、撤回更新、目录移除与不完整读取；只在被可靠来源查询覆盖的范围内核对缓存。真实安装验收不修改源聊天。

## 实现

`HistoryInteractionTrace` 仅读取应用自己的 `history.interactionDiagnostics` 布尔开关，默认关闭。开启时创建本应用 Caches/Diagnostics 下的 0600 JSONL，目录 0700，串行后台写入，最多 2,000 条。关闭时不安装定时器、事件监听或布局探针。记录不含 ID、来源路径、联系人、正文或凭据。

切换从生产选择处理统计到 AppKit 探针布局；消息查询单独统计。滚动只观测本应用的 NSEvent 投递，边界滚动不匹配后来的无关布局。16 ms 主线程定时器记录超过 50 ms 的调度间隔，包含布局与辅助功能查询的影响。

消息列表成为独立视图，滚动阅读位置不直接重建消息内容。分类键按来源复用并在完整目录后清理，时间范围截止只计算一次，同轮布局的底部距离通知合并为最终值。加密缓存读取、解密、解码和头像恢复先在后台完成，通过取消和来源代次检查后发布，再进行实时查询。目录清理累计每页的覆盖状态，任一页不完整均保留旧会话。缓存核验及覆盖边界见 MESSAGE_CACHE.md。

## 重复测量

1. 确认安装版可自动连接；保存并仅开启上述单一诊断偏好，不读取其他偏好或钥匙串。
2. 原生退出、冷启动，交替选择同一大/小会话六次。读取 switch-layout 耗时并保存消息数量，不能拿不同加载量比较，也不能用工具返回耗时代替。
3. 鼠标位于消息区，连续上下滚动六次，中间不逐步查询辅助功能树，最后观察 UI。scroll-delivery 表示事件进入应用，不代表物理屏幕呈现或帧率。
4. 可同时运行 `sample <本应用PID> 30 1 -file <本机私有输出>`。只提交脱敏符号计数，原始采样留在忽略目录。
5. 恢复诊断偏好，原生退出重开，重复切换、滚动、刷新与设置；确认诊断文件时间/大小不再变化，自动连接无需输入凭据。

## 重复缓存 E2E

沿用 LOCAL_SIGNING.md 的现有 Apple Development 证书运行 package-presentation-preview.py。原生退出预览后切换 offline-fixture 场景标记，同证书重签再打开；场景互斥，清理旧结果文件。cache-reconciliation-acceptance 为有限 120 条源，删除第 61 条但保持摘要/日期不变，核对手动刷新、真实文件事件的 60 秒限频更新、撤回正文、未打开缓存、重启、部分覆盖、读取失败、清空与目录移除。输出 JSON 及生产气泡渲染的 cache-before.png / cache-after.png。

同时重复 body-refresh-acceptance、preload-acceptance 与 message-cache-acceptance，核对历史锚点、连续游标、后台刷新、150 会话预热、失败保留与加密缓存。必须实际等待完成，不能以存在旧文件判定通过。全部使用独立合成来源，不操作微信验证删除。

## 判断边界

已证明的缺陷是缓存保留了可靠来源查询不再返回的较早记录，修改前失败证据已保留。尚未获得用户现场的具体会话和时间，不能证明其反馈与此同因。若可靠实时查询仍返回该消息，还需核对微信界面的显示/清理语义；本轮没有猜测 status、盲目屏蔽来源记录或操作微信。

安装版仍有可测的主线程停顿。小样本中位数变化不能证明显著加速；投递、布局、查询和辅助功能查询分别报告，不能声称卡顿完全消除。

## 本轮结果

最终安装 build 72 两次原生冷启动自动连接，主程序与候选包摘要保持一致；设置、关于、刷新、切换和滚动通过。诊断恢复关闭后确认不再写入。23 项完整本机检查与累计 361 项原生合成断言通过；具体源版本边界、失败产物、计时限制与截图见 [验收报告](acceptance/timeline-investigation-20261111/README.md)。

合成大缓存心跳从 1517 ms 降至 302 ms，通过原有 500 ms 门槛。安装版六次缓存切换首次布局中位数 66.6 ms，范围 49.8–140.8 ms；滚轮投递 0.24–6.11 ms。滚动窗口仍记录 93 ms、切换/滚动全过程 223 ms 的最大主线程调度间隔；加入菜单/AX 异常过程后最高 3.65 秒，不能归作连续聊天渲染阻塞，也不能省略该记录。
