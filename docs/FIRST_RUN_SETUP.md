# 桌面应用首次设置

首次打开桌面应用时，初始化引导先检查本机微信记录是否可读，然后进入现有的连接表单。按「稍后设置」可返回欢迎页。以后可随时从「文件 → 初始化设置…」重新打开。

## 设置本机连接

1. 等待权限检查。如果显示「需要授权」，点击「打开系统设置」。在「隐私与安全性 → 完全磁盘访问权限」中添加并开启当前应用。「在 Finder 中显示 we-sync」会选中当前应用包，便于找到它。
2. 返回应用会自动复查，也可以点击「重新检查」。如果 macOS 要求退出并重新打开，按系统提示操作。
3. 状态显示「可读取」后，点击「继续连接」。只有一个可读账户时会预填记录文件夹。多个账户需手动选择对应的 `db_storage`。如果没有发现本机记录，可点击「选择记录…」指定其他位置。
4. 在安全输入框中填写已有的数据库密钥，点击「连接并查看」。选择「记住此连接，下次启动自动打开」后，成功连接会保存在本机钥匙串。尚未取得密钥时，见[密钥设置](PASSPHRASE_ACQUISITION.md)。

打开已有加密备份或导出文件夹时，可以从欢迎页选择相应入口。恢复或浏览这些文件不要求授予应用完全磁盘访问权限。以本机微信记录为来源创建新备份，仍需具备该来源的读取权限。

## 启动与恢复规则

| 情形 | 行为 |
| --- | --- |
| 新用户未配置来源，也未选择稍后设置 | 首次启动显示初始化引导 |
| 用户选择了稍后设置 | 记录延后偏好，重启后回到欢迎页，文件菜单仍可重开引导 |
| 用户打开了指定的导出记录 | 优先打开该记录 |
| 已保存的连接验证成功 | 直接进入历史记录，无需再走引导或输入密钥 |
| 已保存的本机连接因文件权限而失败 | 显示权限步骤；恢复访问后，点「重新连接」重用原钥匙串连接和读取工具绑定 |
| 密钥错误、工具签名或绑定不符、来源损坏 | 走现有连接错误流程；只有实际访问被拒绝才进入权限恢复 |

连接表单在首次连接时只显示连接相关设置。已连接后仍可从「高级设置」配置 AI 读取黑名单和会话显示范围。引导使用当前窗口的原生 sheet，没有额外的主窗口。

## 如何判断能否读取

引导对已选来源或本机候选目录做只读检查，确认 `session/session.db` 和 `contact/contact.db` 可以作为常规文件打开。检查不读取正文、不打开 SQLite、不读取系统 TCC 数据库。访问状态只说明这些文件是否可读。

| 状态 | 可用操作 |
| --- | --- |
| 检查中 | 等待结果，或稍后设置 |
| 需要授权 | 打开系统设置，或在 Finder 中找到应用；恢复访问前不能继续连接 |
| 可读取 | 进入安全连接表单，或使用已记住的连接重新连接 |
| 未找到本机记录 | 手动选择来源，或稍后设置 |

系统设置的授权与数据库密钥分开处理。引导不更改系统权限。CLI 仍由[现有 CLI 配置和连接检查](AGENT_SKILLS.md)管理。

## 重复原生验收

1. 使用同一 Apple Development 证书运行
   `python3 scripts/package-presentation-preview.py --setup --identity EXISTING_CERT_SHA1`。
   如曾选择稍后设置，先退出预览，仅清除预览域
   `me.greenbubbles.SetupPreview` 的 `history.setupGuide.deferred`。
2. 原生打开 `.local-install/we-sync Setup Preview.app`。合成文件默认为不可读。
   确认「需要授权」且继续不可用，点击「打开系统设置」核对目标页面。真实应用的系统授权不参与此步骤。
3. 把 `.local-install/setup-guide-fixture/session/session.db` 改为模式 `0600`，
   返回预览，确认无需点击检查即显示「可读取」。继续进入连接表单，检查来源预填和安全输入框后取消。
4. 从文件菜单重开引导，模拟来源缺失后确认可手动选目录。恢复合成文件并验证「重新检查」。
   点击「稍后设置」，退出并重开预览，确认欢迎页的连接、备份、导出入口均可见。
5. 按[本机签名](LOCAL_SIGNING.md)更新正式应用。保持原证书及工具字节，原生完整退出并重开，
   检查已有连接免输密钥并直接进入历史记录。打开单个会话，确认主动刷新重新查询目录和当前消息。
   仅归档脱敏结果和合成截图。
