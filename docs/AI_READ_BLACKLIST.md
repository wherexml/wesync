# AI 读取黑名单

## 实施前失败场景

- 个人、群聊可同时选择；搜索/切换分类不得丢失勾选，取消不保存。
- 会话时间范围和侧栏分类不能限制可选目录；未加载完应提示并可继续加载。
- 保存失败不能显示成功；损坏/不安全的策略文件必须拒绝 AI 读取。
- 精确 ID、名称解析、批量读取、列表摘要、搜索、附件和旧导出不得泄漏已禁止会话。
- 已运行的服务必须在每次请求重新检查策略。
- UI 本人浏览仍可用，但普通 CLI 参数、环境变量不得冒充原生 UI。
- 重启后策略及已记住连接恢复；不能要求重新输入密钥。
- 测试仅使用合成内容，证据不得包含真实会话 ID、名称、正文或凭据。

## 约定

高级设置中在“会话显示”之前显示“AI 读取黑名单”。选择器复用聊天侧栏的真实名称和头像（没有源头像时显示名称占位），支持搜索个人和群聊，多选后保存。本机所有来源按会话 ID 统一限制，覆盖同一会话的备份；不按可改变的显示名匹配。设置只保存在本机私有文件，不写进仓库。

该策略约束更新后的 GreenBubbles 读取入口，不能撤回 AI 已经读到/另存的内容，也不构成对拥有同一用户文件访问权的任意程序的操作系统隔离。

## 读取边界

- `chats/conversations list` 在 SQL 分页前排除禁止会话，避免摘要和游标泄漏；联系人和名称查找排除禁止项。
- 精确/批量消息读取、指定会话搜索、消息获取、附件访问检查会话 ID。禁止项返回 `aiReadDenied`，不输出正文。
- 有黑名单时，排名、跨会话搜索、旧副本/导出/记忆命令暂时拒绝，避免无法逐条归属的数据泄漏。Connector 每次请求重新检查，已启动的服务也受约束。
- 应用自己的人类浏览通过直接父进程路径、完整应用签名和同证书工具验证区分；没有参数或环境变量跳过开关。路径固定为 `/Applications/GreenBubbles.app`，自定义安装路径不豁免。
- 策略为系统账户 home 下 `Library/Application Support/GreenBubbles/ai-read-policy.json`（0600）。不用传入的 HOME；未知版本、损坏、符号链接或宽松权限拒绝读取。此机制不保护旧版本二进制、已导出的材料或同用户任意文件读取。
- 选择器使用已连接目录，不受时间范围或侧栏分类影响。保留当前目录中暂时不存在的已选项，并提示尚未加载完成；“已选”可统一复查/取消。

## 更新与验收

`stage-local-tool-update.py` 使用既有稳定证书同时签署主读取工具、表情读取工具和应用。签名资源 `ToolUpdate.json` 绑定旧、新工具 SHA-256；只有 bundled 工具、完整签名、相同证书且两端摘要匹配才自动迁移。连接成功后由应用更新自己的记住记录，失败不重写。外部工具保持原有摘要绑定。

1. `swift build -c release --product greenbubbles-history`。
2. `cargo build --release --manifest-path Native/GreenBubbles/Cargo.toml`。
3. `python3 scripts/verify-ai-read-blacklist.py`。仅构造合成 SQLite 数据，临时追加合成黑名单，并在 finally 恢复原策略。运行时不要同时编辑设置。结果 `acceptance/ai-read-blacklist/cli-e2e.json`。
4. 离线 UI：`python3 scripts/package-presentation-preview.py --polish`，在预览包 `Contents/Resources/offline-fixture` 放置空文件 `ai-blacklist-acceptance`，原生打开预览。使用合成人名和群聊检查多选、分类、搜索、取消和保存。
5. 使用现有证书运行 `python3 scripts/stage-local-tool-update.py --identity <证书SHA1> --output <新暂存目录>`。退出已安装应用，保留旧包，安装已校验新包。
6. 从原生 UI 再打开，确认自动重连无需密钥；设置同时选择一个个人和群聊，保存后重新打开/重启保持。本人仍可在应用浏览；CLI 在合成数据源上用选中 ID 验证拒绝，不读取真实正文。验收后恢复用户原选择。
7. `greenbubbles` 命令入口同步指向更新工具；历史副本不具有该保护。仅保存脱敏布尔结果，系统钥匙串确认未完成时记为 BLOCKED，不声称安装验收通过。

## 签名迁移失败场景（实施前）

- 自签证书固定 DR 不代表钥匙串 partition identity 稳定；必须检查 Apple 颁发身份及 Team ID。
- 上次安装尚未成功读取/迁移连接时，记录可能仍绑定前一个工具摘要；签名迁移清单须承接经旧包签名保护的精确前驱摘要，不接受任意工具。
- 新签名身份需要原生授权迁移，不能借助修改 partition list 或全应用开放跳过。
- 同一 Apple 签名身份连续两次资源/程序更新后，应再次退出重开确认不重复弹窗；首次授权和第二次更新分别记录。
